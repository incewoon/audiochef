## 원인

현재는 MP3 파일 전체를 whisper.cpp WASM에 한 번에 넘깁니다 (`src/lib/whisper/transcribe.ts`의 `transcribeMp3`). WASM 인스턴스는 오디오 전체를 16kHz PCM으로 메모리에 올리고 인식 상태도 계속 누적하므로, 길이가 길어질수록 메모리가 커지다 특정 지점(대략 12~15분)에서 WASM heap 한계에 닿아 조용히 abort 됩니다. 이때 예외가 JS로 전달되지 않아 `TRANSCRIBE_TIMEOUT_MS`(15분)까지 대기하다 실패로 끝납니다. 시간 제한 설정값 문제가 아니라 한 번에 처리하는 오디오 양의 문제입니다.

## 해결 방안: 1분 단위 청크 인식

오디오를 **1분 단위**로 잘라 순차 인식하고, 각 결과의 타임스탬프에 청크 시작 오프셋을 더해 하나로 합칩니다.

1. 새 유틸 `src/lib/whisper/chunk.ts`
   - `AudioContext(16kHz)`로 MP3를 디코드해 모노 PCM 확보
   - 60초(`CHUNK_SEC = 60`) 단위로 자르되, 경계는 무음 지점을 우선 선택해 문장이 잘리지 않게 함 (앞뒤 3초 탐색 윈도우)
   - 각 청크를 16kHz 모노 WAV `File`로 만들어 반환 (whisper 입력으로 그대로 사용 가능)

2. `transcribe.ts` 변경
   - `transcribeMp3`을 내부 단일 실행 함수 + 청크 루프 구조로 분리
   - 청크마다 **새 FileTranscriber 생성 → 인식 → 즉시 destroy**. 메모리 누적 없음 (기존 1회성 인스턴스 정책 유지)
   - 각 세그먼트에 `offsetMs`를 더해 실시간 `onSegment` 콜백으로 전달 → 진행 중 가사가 계속 쌓임
   - 진행률은 (완료 청크 수 + 현재 청크 진행률) / 전체 청크 수 로 환산
   - 타임아웃은 전체가 아니라 **청크 단위(약 3분)** 로 적용. 특정 청크가 실패해도 그 구간만 건너뛰고 다음 청크 계속 진행, 마지막에 모인 결과 반환
   - 1분 이하 파일이면 청크 1개로 기존과 동일 동작

3. `LyricsDialog.tsx`
   - 진행 표시에 "Part 3 / 12" 같은 청크 진행 정보 추가 (영문 UI 유지)
   - 취소 버튼이 현재 청크 중단 + 루프 종료로 동작하도록 연결
   - 기존 무음 정렬(`snapSegmentStarts`, `splitOnSilence`)은 합쳐진 전체 결과에 그대로 적용

## 기술 메모

- 청크 크기는 상수(`CHUNK_SEC = 60`)로 두어 조정 가능
- 청크가 짧으면 인스턴스 생성 오버헤드가 반복되므로, 모델 blob은 한 번만 로드해 재사용하고 transcriber만 청크마다 교체
- 문맥 유실을 줄이기 위해 각 청크 앞에 이전 1초를 겹쳐 넣고, 겹친 구간에서 나온 중복 세그먼트는 타임스탬프 기준으로 제거
- 오프라인 동작·모델 캐시·기존 필터(음표 제거) 로직은 변경 없음
